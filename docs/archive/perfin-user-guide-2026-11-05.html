01 · Start here

PerFin turns locally stored statement files into reviewed transactions, an auditable ledger, Excel views, debt scenarios and personal financial statements.

Windows release acceptance is pending

The source is implemented, but actual Windows/ACE, desktop Excel, VBA and Power Query acceptance remains unverified. This guide is not a certified Windows release. Start in a fresh synthetic data folder.

Understand

Excel modules

Read-only core views, editable payoff assumptions and queued valuation inputs.

Your shortest route

  1. Install and check the environment.
  2. Complete the synthetic first-use walkthrough.
  3. Run native acceptance and keep the evidence.
  4. Start a separate real-data root, validate your bank’s CSV mapping, then repeat the reviewed workflow.

The small Tkinter GUI covers file selection, CSV staging, preview, review, commit, transfer linking, refresh and backup. The CLI covers the broader workflow. This HTML is a guide, not the PerFin application; its controls do not access your financial files.

04 · Install and prepare

Target: Windows with desktop Excel and compatible Access/ACE runtime, Python and pyodbc bitness. The project declares Python ≥3.10; the historical Linux checks used 3.12.14. Full Access is needed for design/query maintenance. No Windows/Office combination is certified by this guide.

  1. Clone or download PerFin into a local source folder. A clean Git checkout is needed for the revision-aware release runner and packaging.
  2. Open Command Prompt in that folder. The commands in this guide use CMD syntax, not PowerShell.
  3. Create a virtual environment and install the declared extras:
Windows Command Prompt · activated environment
py -m venv .venv
.venv\Scripts\activate
python -m pip install ".[windows,pdf]"
perfin envcheck

Stop and resolve missing ACE/ODBC or bitness mismatches before creating a database. Installation can download packages. For disconnected installation, use a reviewed local wheelhouse with --no-index --find-links; see the release runbook.

Windows Command Prompt · activated environment
set "PERFIN_DATA=%LOCALAPPDATA%\PerFin-synthetic"
perfin --data-root "%PERFIN_DATA%" init --demo
perfin --data-root "%PERFIN_DATA%" status
perfin --data-root "%PERFIN_DATA%" gui

Use a new folder if this root already contains a database: init refuses overwrite. --demo adds chk:main ($2,500), card:a ($200 owed) and card:b ($100 owed), opening January 1, 2026; it creates no imported history. Close the GUI before continuing with another operation.

Start real records only in a separate root

Windows Command Prompt · activated environment
set "PERFIN_DATA=%LOCALAPPDATA%\PerFin"
perfin --data-root "%PERFIN_DATA%" init
perfin --data-root "%PERFIN_DATA%" onboard C:\Private\accounts.json

Prepare accounts.json as a validated ledger_bundle with your account IDs, opening dates/balances and categories. The household example is a format reference, not your data. Onboarding is insert-only; existing IDs are refused. A single account can be added with:

Windows Command Prompt · activated environment
perfin --data-root "%PERFIN_DATA%" account-add chk:bank --name "Checking" --kind asset --class checking --opening-cents 100000 --opening-date 2026-01-01

The last line is illustrative: 100000 cents = $1,000.00. Substitute an opening balance before the first imported activity so it is not counted twice.

Keep private data outside the source folder

Use a local, nonsynced data root. CSVs/PDFs, populated databases/workbooks, reports, commands and backups all remain private. Checkout paths are refused; sync/network locations have additional guards. Use the recommended local path instead of bypassing them.

06 · Import, review and correct

Choose the exact CSV profile

Check the encoding, headers, delimiter, date format, decimal separator and sign convention against the actual export. Headers match exactly. Built-in profiles are synthetic, not verified bank integrations. For a new format, use profile-create for a basic signed-amount file, or a local JSON profile for supported debit/credit columns, preambles and footers. Bump the profile version when its mapping changes.

Profile / conventionMeaning
synthetic_checking_signedUTF-8, MM/DD/YYYY, amounts as-is; synthetic running balance and transaction ID columns.
synthetic_checking_debit_creditCP1252, M/D/YYYY; canonical amount = credit − debit.
synthetic_card_invertedUTF-8 with BOM; invert positive purchases and negative payments/refunds.
Canonical signsPositive = more asset value or less debt. Negative = less asset value or more debt.
NumbersMoney is integer cents internally. Input parsing requires declared separators and 0 or 2 decimal places; malformed amounts are errors, not zero.
Dates03/04/2026 depends on the selected format. Invalid dates are refused; dates are never guessed or swapped.

Every import is a review queue first

  1. Stage the file with import; inspect preview BATCH_ID.
  2. Compare row count, dates, signs, descriptions, running balances and totals with the original.
  3. Inspect errors, duplicate evidence, category suggestions and ambiguous transfers.
  4. Approve only valid rows; reject unwanted rows with a reason. Decide every row before committing.
  5. Commit explicitly. The repository rechecks errors, duplicates, references and split sums in one atomic transaction.
Windows Command Prompt · activated environment
perfin --data-root "%PERFIN_DATA%" review BATCH_ID --reject 3 --reason "Confirmed duplicate"
perfin --data-root "%PERFIN_DATA%" review BATCH_ID --resolve 4=confirmed_distinct
perfin --data-root "%PERFIN_DATA%" review BATCH_ID --approve 1,2,4
perfin --data-root "%PERFIN_DATA%" commit BATCH_ID

These IDs and row numbers are templates, not the walkthrough’s next action. Resolve a duplicate as distinct only after comparing source evidence. A confirmed_duplicate decision still needs explicit rejection. If another import introduces a source-ID collision after staging, commit can refuse the whole batch; re-review the collision and retry deliberately.

Review states and safe recovery
State / symptomAction
pending / needs_reviewInspect; neither is approval. Parse errors cannot be approved.
possible duplicateResolve as confirmed_distinct if proven legitimate; otherwise reject.
approvedApproved rows post only after the whole batch meets commit rules.
rejectedExcluded from posting; reason remains in the audit trail.
Exact same-file replayUse the existing batch. Repeated commit must not create more transactions.
Rolled-back fileSame-file reimport is refused by the app/schema. Use audited corrections; never change a hash to bypass replay.
Stale workbook commandRefresh the reports/workbook, review again, then issue a new command. Do not replace its version token automatically.

Categories and corrections

Default categories are expenses and income. The importer can propose categories through optional rules, but the frozen command interface does not provide a general staging-category editor. Posted recategorization and multi-category splits use validated edit_transaction / set_splits command documents.

Windows Command Prompt · activated environment
perfin --data-root "%PERFIN_DATA%" command C:\Private\correction.json

Use the current command contract and expected row versions. Splits must sum to the transaction amount. Reversals preserve history; linked transfer legs must be unlinked before reversal. Batch rollback creates dated reversals and is refused when transactions are reconciled, payment-allocated or transfer-linked. Do not repair records by editing Access tables or deleting audit rows.

07 · Reconcile and understand payments

Reconciliation compares a selected set of posted transactions with a statement’s signed opening and closing balances. Record the statement first, then select the actual included transaction IDs.

Windows Command Prompt · activated environment
perfin --data-root "%PERFIN_DATA%" statement-add july --account card:a --start 2026-07-01 --end 2026-07-31 --opening-cents -20000 --closing-cents -15000 --due-date 2026-08-25 --minimum-cents 2500
perfin --data-root "%PERFIN_DATA%" reconcile july --transactions TXN_ID_1,TXN_ID_2

This template balances only when the selected activity is +5000 cents. A card’s owed balance is negative in the ledger; Excel can display the same debt as a positive amount owed.

Synthetic arithmetic lab

Opening + activity − closing = difference

Change the numbers to see a mismatch. Integer cents only. This illustrates the identity; it does not run PerFin’s validation or read a statement.

Difference: 0 cents — balanced arithmetic

Link the two sides of a card payment

A checking outflow of −$100 and a card inflow of +$100 are one transfer. Link matching whole transactions on different accounts, in the same currency. The link removes the payment from income/expense categories. A refund is different: a positive expense-category split reduces spending.

Windows Command Prompt · activated environment
perfin --data-root "%PERFIN_DATA%" link-transfer CHECKING_PAYMENT_TXN CARD_PAYMENT_TXN

Whole-leg linking cannot express only the principal part of a mixed mortgage payment. Advanced split-transfer data requires the documented bundle/contract route. Do not classify interest as a transfer.

Minimum due, unpaid amount and utilization

Card status uses the latest eligible statement and effective terms. A transfer link alone is not a statement-payment allocation: recorded allocations determine payments against a specific statement. Use allocate_statement_payment through a validated command when that attribution is needed. No payment is sent.

Missing or zero credit limits produce null/unknown utilization, not 0%. PR #23 guards the Access divisor; existing databases retain old saved queries until refreshed. Before updating saved queries with CreatePerfinReportQueries, back up and test on a synthetic copy in full Access. This is not an automatic migration.

09 · Plan credit-card payoff

The payoff engine compares strategies without modifying transaction history or executing payments. Its separate workbook lets you change assumptions and explicitly recompute.

Practice with the repository’s scenario

Save it under %PERFIN_DATA%\demo-inputs. It has $8,000 of invented debt, a $600 monthly budget and a $1,000 month-3 lump sum. Statement references are null: this is a what-if, not a verified current-balance plan.

Windows Command Prompt · activated environment
python -m perfin_excel_payoff install "%PERFIN_DATA%\demo-inputs\scenario.synthetic.json" --data-root "%PERFIN_DATA%"
perfin --data-root "%PERFIN_DATA%" refresh --as-of 2026-11-01

Open workbooks\excel_payoff\PerFin-Payoff.xlsx. Installation writes the module manifest beside the workbook; the refresh makes it discoverable in Modules.

StrategyAllocation after all minimums
Largest balanceTarget the largest remaining balance.
SnowballTarget the smallest remaining balance.
AvalancheTarget the highest remaining APR; dynamically rerank.
Near-APR hybridSelect cards within the chosen percentage-point band below the highest APR, then prefer largest or smallest balance.
  1. Edit blue cells on Inputs, Cards and Cash events. APR cells use percentages; money uses dollars to cents.
  2. Use event kinds override, lump_sum, charge or fee. Charges/fees need an account; budget events leave it blank.
  3. Save and close Excel, recompute, then reopen. The stale-input formula is a warning, not the engine itself.
Windows Command Prompt · activated environment
python -m perfin_excel_payoff recompute "%PERFIN_DATA%\workbooks\excel_payoff\PerFin-Payoff.xlsx" --data-root "%PERFIN_DATA%"

To store revised assumptions in Access, queue and apply them:

Windows Command Prompt · activated environment
python -m perfin_excel_payoff save-command "%PERFIN_DATA%\workbooks\excel_payoff\PerFin-Payoff.xlsx" --data-root "%PERFIN_DATA%"
perfin --data-root "%PERFIN_DATA%" process-outbox

Alternatively, perfin … payoff SCENARIO.json computes, saves and builds through the application path. Existing workbooks require explicit --replace; preserve unsaved edits first.

Build from reconciled current balances

Windows Command Prompt · activated environment
perfin --data-root "%PERFIN_DATA%" payoff-current --as-of 2026-07-31 --monthly-cents 60000

Each owed card needs explicit supported APR/minimum terms and a balanced latest statement. Current debt includes later posted activity through the as-of date; it need not equal that statement’s closing balance. Missing or promotional/calendar/multi-bucket/deferred-interest terms are refused by this current-ledger adapter. Record terms with validated set_card_terms commands; do not invent them.

Calculation assumptions and refusal states

Interest is opening debt × APR/12, rounded half-up once per card per month. Fees/charges are added after interest; their first interest is next month. All minimums are paid before extra allocations, with capped final payments and immediate spillover. Unspent budget does not carry forward automatically.

Month 1 is one calendar month after As of, clamped to month-end. A 0.5 near-APR gap means 0.5 percentage points. Optional target locking can cost more than dynamic avalanche.

ResultInterpretation
FinishedPayoff date and completed-run cost comparisons may be available.
infeasible_budgetBudget cannot cover all minimums. The model accrues that month but simulates no payments for it.
unsupported_termsMulti-bucket or deferred-interest terms are not flattened into a blended APR.
Horizon exhaustedRemaining debt stays visible; payoff date remains null.
Incomplete comparisonLifetime savings/tolerances are not meaningful unless both compared runs finish.

The standalone engine supports a simple single-bucket introductory rate with month-based expiry. It does not support daily-balance accrual, grace periods, issuer-specific allocation or residual interest. This is an approximate planning model, not a lender statement or a claim of global optimality. Mortgage tools belong to the optional toolbox.

10 · Statements, valuations and net worth

Windows Command Prompt · activated environment
perfin --data-root "%PERFIN_DATA%" statements --as-of 2026-07-31 --period-start 2026-07-01

This reads Access and writes workbooks\excel_statements\PerFin-Statements.xlsx. Summary, Accounts, Income, Cash flow and Bridge are views; Valuations is the explicit input area. The output reports coverage and warnings. Opening an old workbook does not refresh it.

RuleWhat to do
Valuation-required assetsRetirement, brokerage, property, vehicles, business and other assets need dated whole-account values. Missing values are excluded with warnings, not silently assumed zero.
End-of-day valueA valuation includes activity on its date; only later posted activity is added.
Ownership / debt responsibilitySet asset ownership independently from legal debt responsibility. Integer percentages are supported. A half-owned property does not automatically halve the mortgage.
Avoid double countingChoose account totals or holdings, and property + debt or equity. Configure explicit inclusion_groups for mutually exclusive representations.
LiquidityLiquid net worth is the signed subtotal of accounts tagged liquid, not all liquid assets less every household debt.

Add a dated valuation

  1. On Valuations enter stable account ID, date, value in currency units, currency, source and method. Methods: statement, market_close, appraisal, automated_estimate or owner_estimate.
  2. For a new value, leave Existing version blank. An optional blank valuation ID becomes a stable account/date ID. Set Queue = Yes.
  3. Save and close Excel. Queue selected rows, inspect/apply the resulting commands, then rebuild:
Windows Command Prompt · activated environment
python -m perfin_excel_statements queue-valuations --workbook "%PERFIN_DATA%\workbooks\excel_statements\PerFin-Statements.xlsx" --data-root "%PERFIN_DATA%"
perfin --data-root "%PERFIN_DATA%" process-outbox
perfin --data-root "%PERFIN_DATA%" statements --as-of 2026-07-31 --period-start 2026-07-01
perfin --data-root "%PERFIN_DATA%" refresh --as-of 2026-07-31

Queueing validates all selected rows before writing any command. It rejects formulas and fractional cents. Correct an existing valuation using its current row_version; new dates preserve history. Queue or separately save unsent rows before rebuilding, because rebuild replaces the workbook.

Read the bridge as a diagnostic

Opening net worth + income − expenses + valuation change + other change = closing net worth

“Other change” is an unclassified residual needing investigation. Arithmetic agreement does not prove bank reconciliation or complete records. Transfers and included debt principal movements should not create a second expense; interest does.

11 · Backups, recovery and upgrades

Create a backup while everything is closed

Close Access, Excel, the GUI and other database users. The command obtains a summary, closes its own connection and makes a hashed backup set. Lock files or a failed Windows exclusive-open probe block backup.

Windows Command Prompt · activated environment
perfin --data-root "%PERFIN_DATA%" backup

Keep the returned backup-set path. The manifest records file sizes/hashes, versions, balances and history. A changing source or a failed integrity check aborts the copy.

Know what was backed up

The application command includes the database and its manifest. It does not automatically include original CSV/PDF statements, custom profiles, commands or unsaved workbook inputs. Preserve those supporting files separately. The lower-level API accepts extra files, but the current app CLI does not expose that option.

Restore to a new file, then inspect

Windows Command Prompt · activated environment
perfin --data-root "%PERFIN_DATA%" restore "BACKUP_SET_PATH" --target db/perfin-restored.accdb

Replace the placeholder with the backup path. The target must not already exist. Restore verifies hashes before writing, opens the copy through the repository and compares balances, history, statements, row counts and schema with the manifest. A mismatch removes the failed restored copy.

Restore does not switch the active app. The main CLI still opens db/perfin.accdb. Inspect a recovered candidate using the lower-level store command before choosing it:

Windows Command Prompt · activated environment
python -m perfin_store export-bundle --db "%PERFIN_DATA%\db\perfin-restored.accdb" > "%PERFIN_DATA%\exports\restored-ledger.json"

Create exports first if it is absent. The exported JSON is private. Compare it with the backup manifest and any pre-incident snapshot. A successful restore proves consistency with that backup, not that the backup contains your latest work.

Deliberate activation and upgrade checklist
  1. Keep a verified backup and the code revision/dependency versions that can open it.
  2. With all database users closed, preserve the existing active database under a separate recovery name; never overwrite your only copy.
  3. Only after verification, place a copy of the recovered database at the app’s expected db/perfin.accdb path. There is no automatic “switch restored database” command.
  4. Run status and regenerate reports/workbooks; verify balances and history again. Keep the previous copy until acceptance succeeds.
  5. Restore separately preserved source files/profiles if needed. Rebuilding reports cannot recreate missing original statements or unsent workbook input.

Version checks refuse unsupported/newer schemas. There is no general migration chain yet. If an upgrade cannot be completed, return to the matching prior backup/code pair; do not bypass schema checks.

Existing saved-query correction

PR #23 fixes zero-limit utilization in new database setup. Existing databases need a saved-query refresh using access/setup/PerfinSetup.bas and CreatePerfinReportQueries in full Access. Back up and verify on a synthetic copy first; the fix does not automatically rewrite a user database.

What the arrows mean

Each reference points from a child field to a parent's primary key. A parent can usually have many child rows. The database enforces these declared links; the repository enforces the financial meaning.

  • Transfers: one link names two equal-and-opposite transactions on different same-currency accounts. Transfer splits connect each leg to that link.
  • Statements: payment allocations and reconciliation membership are separate relationships. A payment allocation is not a second transaction.
  • History: audit rows reference a command and keep before/after images. Their entity reference is logical so historical evidence can survive deletion.
Amber notes identify logical links without a SQL foreign key.

SQLite uses STRICT tables and explicit foreign-key enforcement. Canonical TEXT columns use NOCASE; ASCII folding does not prove equivalence with every ACE locale. contract_meta identifies backend=sqlite, sqlite_schema_version=1 and report_views=python_export.

Excel can run in two modes

Python builds report data and workbook files in a cloud or local development environment using synthetic fixtures. SQLite uses those canonical report exports rather than translating Access SQL views.

Desktop Excel recalculation, VBA, Power Query and Access/ACE behavior still need native acceptance before claiming those release capabilities. Those checks do not prevent further development.

What a later port must preserve

Matching table names alone does not establish compatibility. A full-history port must preserve staging decisions, exact money, audit rows, command replay, relationships, versions and metadata, then compare balances and history.

A ledger bundle is useful exchange data, but does not contain every staging/audit record. Renaming a file or copying only report rows cannot produce an equivalent database. See the portability contract and the full model document.
